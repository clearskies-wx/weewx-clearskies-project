### `weewx_clearskies_marine/services/invariants.py`

Registry pattern (see file in full, 337 lines): one module-level constant
`INVARIANT_N = "N:slug"` per invariant (currently `INVARIANT_1`..`INVARIANT_10`,
lines 54–101), so a name used at a call site and a name asserted in a test
cannot drift. Firing is via `invariants.check(name, ok, detail, *,
spot_id=None, valid_time=None, transect_index=None, **context)` (def at
124–156) — logs one ERROR and records to a bounded ring buffer on `ok=False`,
returns immediately (no-op) on `ok=True`, and **never raises** (wraps its own
body in try/except). Call sites pass `ok` as the already-evaluated boolean
condition — the invariant module does no computation of its own beyond
bookkeeping. `get_invariant_state()` (176–205) is B3/health's read
interface. The two new X-D3/X-D4 fire-only invariants (closure,
`marched ≤ raw + 1mm`) slot in as `INVARIANT_11`/`INVARIANT_12` with calls
at their natural production sites: the closure check inside/after the
roller march step in `surf_1d_analytical.py` (wherever X3 adds it, near
`_ddd_breaking_march`/`apply_ddd_saturation`), the no-gain check inside
`apply_ddd_saturation`'s breaking branch (near the deleted line 720) and/or
`_ddd_breaking_march`'s (near line 604).
