## Lead mechanics (binding; a deviation is a finding to report BEFORE coding)
1. **Placement.** In `service.py::_run_ww3_leg()`, the hook runs ONCE, immediately after `ww3_leg_dict`
   is loaded (`:732–741`) and BEFORE the restart-chaining block (`:743`), because its outcome decides
   `cold_start`. Today's `mod_def.ww3`-missing refusal (`:996–1013`, `ww3_mod_def_missing`) stays where it
   is and stays byte-identical — after a successful rebuild it simply finds the new file. The horizon
   march (`_run_ww3_horizon_march`, `:1325`) is NOT touched: it consumes only (T13: the rebuild can never
   run twice per cycle; the march never rebuilds).
2. **The derivation the hook compares.** Add `swan_domain.ww3_setup_derivation_from_dict(d) ->
   WW3SetupDerivation` (the inverse of `ww3_setup_derivation_to_dict()`, `swan_domain.py:3724` —
   `time_steps` and `boundary_cells` dataclasses reconstructed; the five S8.1-A keys read when present,
   `None` when absent; `deck_text` ignored on input, it is re-derived by `build_ww3_grid_deck()`).
   Round-trip `from_dict(to_dict(x))` must reproduce every field (KAT). Put it beside `to_dict`.
3. **`derivation_sha256`** = SHA-256 over exactly what `ww3_grid` consumes: the UTF-8 bytes of
   `build_ww3_grid_deck(derivation)` followed by the bytes of `G1_bottom.txt`, `G1_status.txt`,
   `G1_obstr.txt` as written by `ww3_grid_files.write_ww3_grid_name_files()` (in that fixed order,
   each preceded by its filename + `\n` so boundaries are unambiguous). NOT over the sizing JSON
   (its `provenance` block carries timestamps and would rebuild every cycle). Implement as
   `ww3_grid_files.derivation_grid_sha256(derivation, name_file_paths) -> str` (pure; hashes files
   already written to the staging dir). Hash function: `hashlib.sha256`, streaming, never whole-file
   reads of large files (mirror `ww3_runner._sha256_of`).
4. **Inputs missing.** If `ww3_leg_dict` has no `depths`/`status`/`transparency` (a sizing JSON minted
   before S8.1-A, or a derivation whose CRM fetch failed): when `mod_def.provenance.json` exists and
   `mod_def.ww3` exists → proceed exactly as today (no rebuild possible, none needed); when the note
   is missing or unreadable → refuse the cycle with the NEW named reason `ww3_grid_rebuild_inputs_missing`
   (`state.record_ww3_leg_refusal(..., derivation_present=True)`), log ERROR naming the sizing cache path
   and that the grid-sizing chain must re-run with the CRM fine DEM. No ETOPO substitution, no
   on-the-fly derivation (the sizing chain is the only place `derive_ww3_setup()` runs).
5. **Decision.** Read `level0/mod_def.provenance.json` (`{"derivation_sha256": str, "rebuilt_at": ISO-8601 UTC,
   "cycle_time": str, "reason": "provenance_missing"|"derivation_changed", "previous_file": str|null,
   "fine_dem_source": str|null, "deck_sha256": str, "name_file_sha256": {name: hex}}`). Rebuild when the
   note is missing, unreadable, lacks `derivation_sha256`, OR its value ≠ the current hash. Equal → no
   rebuild, no file writes, the cycle continues byte-identical to today (KAT: `run_grid` never called).
6. **Rebuild.** Staging dir `level0_dir / f"grid_{token}"` (token = `_ww3_cycle_token(cycle_dt)`; created
   fresh, removed in `finally`): write the deck and the three NAME files there;
   `WW3StepSpec(deck_text=deck, input_files={the three NAME files by their exact names}, expected_outputs=["mod_def.ww3"])`;
   build the `WW3RunnerConfig` ONCE (hoist today's `:1090–1112` block above the hook and reuse the same
   `runner_config` / work-root mkdir / `ww3_work_root_failed` refusal for both the hook and the leg —
   no second copy of the config code); `runner.run_grid(spec, dest_dir=staging_dir)`. On success:
   if `level0/mod_def.ww3` exists, `os.replace` it to `level0/mod_def.ww3.prev-<token>`; then
   `os.replace` the staged `mod_def.ww3` into `level0/mod_def.ww3`; then write the provenance note
   (atomic: write `.tmp` then `os.replace`). On `WW3RunError` (or any OSError in the promote/notes):
   log ERROR with `exc.reason`, refuse the cycle with `ww3_grid_rebuild_failed`, leave the existing
   `mod_def.ww3` and note UNTOUCHED (KAT), return. Retention: keep every `mod_def.ww3.prev-*` (876 KB
   each, rebuilds are rare) — `_prune_ww3_level0` is NOT to be taught about them this round.
7. **Cold start after a rebuild.** When the hook rebuilt this cycle: skip the restart-chaining block
   entirely — set `cold_start = True`, `restart_age_h = None`, log WARNING
   `"WW3 leg: mod_def.ww3 rebuilt for cycle %s (reason=%s) -- restart %s refused: ww3_grid_rebuilt_cold_start; cold-starting"`.
   The cycle then proceeds exactly as today's cold-start path (no `restart.ww3` in `march_inputs`).
   The existing restart file is NOT deleted (it is a valid artifact of the previous grid; the next
   cycle's restart comes from this march). The `ww3_grid_rebuilt_cold_start` slug is recorded in state
   (item 8) — it is NOT a `record_ww3_leg_refusal` (the cycle runs).
8. **State + health (additive, `state.py`).** `_ww3_leg` gains `gridRebuiltAt: str|None`,
   `gridRebuildReason: str|None` (`provenance_missing` / `derivation_changed`), `gridDerivationSha256: str|None`,
   `gridRebuildCycleTime: str|None`, `restartRefusedReason: str|None` (set to `ww3_grid_rebuilt_cold_start`
   on the rebuild cycle, cleared to `None` by the next `record_ww3_leg_success`/`record_ww3_leg_refusal`).
   New `state.record_ww3_grid_rebuild(cycle_time, *, reason, derivation_sha256)` (never raises, persists the
   snapshot like its siblings). `GET /health`'s `ww3` block picks them up automatically (`health.py:286–296`
   spreads the state dict) — verify, do not duplicate. `_KNOWN_*` allow-lists in `state.py`/tests: check
   for a pinned key set and report if one exists (a stale pin is a finding, not something to widen silently
   — the test-author owns test edits).
9. **Docs (meta, separate commit).** OPERATIONS-MANUAL: new subsection under the WW3 leg story (`:1458` ff.,
   after "Disk/retention") — "WW3 grid rebuild (G10 hook)": what triggers it, the files it writes, the
